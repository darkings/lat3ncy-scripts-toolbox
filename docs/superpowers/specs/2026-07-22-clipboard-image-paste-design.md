# 剪贴板图像粘贴设计

> **迁移说明：** 本文记录迁移前的 `D:\Scripts` 路径与结构，仅作历史参考；当前仓库结构以 [`2026-07-22-script-toolbox-migration-design.md`](2026-07-22-script-toolbox-migration-design.md) 为准，不应将本文视为现行操作指南。

## 目标

扩展 `ahk/productivity.ahk` 中现有的 `Ctrl+Shift+V` 快捷键，使它根据剪贴板内容和活动窗口选择合适的粘贴行为，同时保留当前的纯文本粘贴能力。

## 行为

1. 按下 `Ctrl+Shift+V` 时，优先判断剪贴板是否包含可读取的位图。
2. 如果包含位图且活动窗口是 Windows 资源管理器，将位图保存到该窗口当前显示的文件夹。
3. 保存文件采用 `Clipboard-yyyyMMdd-HHmmss.png` 命名；发生同秒重名时追加递增序号，禁止覆盖已有文件。
4. 如果包含位图但活动窗口不是资源管理器，发送普通的 `Ctrl+V`，由当前应用处理图片粘贴。
5. 如果不包含位图，继续使用现有的 `SendText A_Clipboard` 进行纯文本粘贴。
6. 剪贴板同时提供图像和文本格式时，图像优先。

## 实现结构

- 保留 `Ctrl+Shift+V` 的现有热键注册，将处理函数扩展为内容分派器。
- AHK 通过 Windows 剪贴板格式检查判断是否存在位图，不为了检测而修改剪贴板。
- AHK 通过 `Shell.Application` 和活动窗口句柄取得当前资源管理器目录。无法得到真实文件系统目录的虚拟位置不执行保存。
- 图片保存交给以 STA 模式启动的 Windows PowerShell，使用 .NET Windows Forms 和 Drawing API 读取剪贴板并编码为 PNG。
- PowerShell 进程返回成功后显示已保存文件名；失败或目录不可写时显示简短错误提示。

## 错误与边界

- 剪贴板图像在检测后被其他程序替换时，保存可能失败；脚本提示失败，不回退保存旧内容。
- `此电脑`、搜索结果等没有普通文件系统路径的位置视为不可保存，并显示提示。
- 目录无写权限、PowerShell 启动失败或图像解码失败时，不创建残缺文件，并显示失败提示。
- 普通文件复制产生的文件列表不视为位图，仍进入原有文本分支；本功能不改变资源管理器的普通文件粘贴。

## 验证

- 文本剪贴板在编辑器中仍以纯文本方式粘贴。
- 截图或复制的位图在资源管理器中生成有效 PNG，且源剪贴板保持不变。
- 连续保存不会覆盖已有文件。
- 图像在支持图片粘贴的非资源管理器应用中走普通 `Ctrl+V`。
- 虚拟目录和不可写目录给出错误提示，不遗留零字节文件。
